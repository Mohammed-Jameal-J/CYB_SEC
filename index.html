🔢 Sequence Numbers — why handshake really needs 3 steps

DEFINITION: Ovvoru side random-ah oru "Initial Sequence Number" (ISN) pick pannும் — idhு data ah correct order-la reassemble panna and duplicate/lost packets detect panna use aagும்.

SYN packet-la client-oda ISN (seq=x) irukும். Server SYN-ACK-la thanoda ISN (seq=y) + client ISN ah acknowledge pannும் (ack=x+1) — rendு things one packet-la. Client final ACK-la server ISN ah acknowledge pannும் (ack=y+1).

⚠️ Security relevance — Session HijackingISN random-ah illama predictable-ah irundhா (old Unix systems-la idhு irundhுchu), attacker SYN-ACK ah paakaமலேயே, victim-oda session-ku packets inject panna mudiyும் — idhுthaan classic Mitnick-style IP spoofing attack. Adhுthaan modern systems randomization mandatory-ah pannirukku.

DEFINITION: Attacker thousands of SYN packets anுப்பும், aana step 3 (final ACK) never complete pannாthு — server "half-open" connections-ku slot allocate panniyே backlog queue exhaust aagும்.

Power button = oru simple switch mattum thaan, adhுக்கு own power illa. Neenga press panна, andha switch PSU (Power Supply Unit)-ku signal anுப்பும். PSU dhaan wall socket-la irundhu AC current eduthu, DC current-ah convert panni, motherboard-ku + CPU-ku + RAM-ku + Storage-ku ellame separate cables mூலம் power kudukkும். ↓

↓

↓

↓

↓

↓

↓

↓

↓
🔟 System services/daemons start in background
↓

Correction noteBIOS/UEFI is firmware stored on a small chip on the motherboard itself — it doesn't "load ON hardware" from disk. It's the very first code that runs, and its only job is: test hardware (POST) → hand control to the Bootloader, which lives on your storage drive.

🔁 Symmetric Encryption — Same key, both sides

DEFINITION: Encrypt panna use panra key-um, decrypt panna use panra key-um SAME key.
Symmetric flow
Plain text: "Hello Amazon"
↓ (Key: X7f9!)

↓ (SAME Key: X7f9!)

🔓🔒 Asymmetric Encryption — Public + Private key pair

DEFINITION: Rendu vera keys — Public key (everyone-ku share pannலாம்) + Private key (secret, yaarukkum kudukka koodadhu).
Asymmetric flow — key exchange
Amazon server: Public key + Private key generate pannும் (RSA algorithm)
↓

↓

Amazon mattum thaan Private key vechi adha decrypt panna mudiyum — session key safely share aayiduchu

🤝 Diffie-Hellman Key Exchange — vera oru method

DEFINITION: Rendu parties, PUBLIC channel-la pesikittேyே, oru common secret key create pannிக்கும் method — actual key never network-la travel pannாthு.
Simplified analogy — paint mixing
Both agree publicly: "Yellow" paint (public, everyone paakalam)
↓
You add secret "Red" → Orange | Server adds secret "Blue" → Green
↓
Rendu peruma Orange and Green mixed colors ah exchange pannும் (public-ah)
↓
Each side, other person's mix + own secret add panna, SAME final color varum — attacker-ku andha final color reproduce panna mudiyathu (secret theriyathu)

  • Older TLS versions
  • No "forward secrecy" by default

  • Forward secrecy — old sessions safe even if key leak aanaலும்

#️⃣ Hashing — One-way transformation

DEFINITION: Data ah fixed-length code-ah convert pannும், aana decrypt panna MUDIYADHU (one-way). Password store pannradhukku use pannுவாங்க, encryption-ku illa.
